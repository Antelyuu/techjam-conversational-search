Shopping Agent: Source Documentation

A source-based guide to the current TikTok TechJam Track 4 starter agent. It documents what the code does today, not a proposed future architecture.

Executive summary

The agent is a stateless lexical retriever. It tokenizes the latest user message, builds an SQLite FTS5 OR query, ranks matching catalogue records with BM25, and returns product parent_asin values.

Request flow: catalogue → SQLite FTS5 index → latest message → tokenization → keyword query → BM25 ranking → recommendations → evaluator scoring

Methods in starter/agent.py

_text(value) — lines 17–24

Converts catalogue fields into searchable strings. Dictionaries become key value pairs, lists become space-separated text, and missing values become an empty string.

_text({"department": "womens"})  →  "department womens"
_text(["walking shoe", "lightweight"])  →  "walking shoe lightweight"

_terms(text) — lines 27–32

Extracts lowercase alphanumeric tokens using TOKEN_RE, removes one-character tokens and the fixed STOPWORDS set, and returns a list. It does not understand that a number after “under” is a price constraint.

_terms("Black running shoes under $120")
→ ["black", "running", "shoes", "under", "120"]

Agent.__init__(catalog_path) — lines 38–42

Stores the catalogue path, opens an in-memory SQLite connection, creates an empty session-ID set, and builds the search index. Because the database is :memory:, the catalogue is indexed again each time an Agent is created.

_build_index() — lines 44–71

Creates an FTS5 virtual table and loads every catalogue row in batches of 1,000. FTS5 is SQLite’s full-text search feature. The indexed fields are title, categories, features, details, store, and description; parent_asin is stored but marked UNINDEXED.

The catalogue is expected at data/catalog.jsonl. The current checkout does not contain that file.

reset(session_id, user_profile) — lines 73–75

Marks a session as initialized. Although the profile is passed in, the current code ignores it. No conversation history or constraints are stored.

respond(session_id, user_message, turn, top_k) — lines 77–102

  1. Rejects calls for sessions that were not reset.
  2. Tokenizes only the current message and keeps at most 40 terms.
  3. Joins terms with OR, so any matching term can qualify.
  4. Runs FTS5 search ordered by BM25.
  5. Converts returned ASINs to the evaluator’s recommendation format.
  6. Returns a generic message, no clarification attribute, and zero reported tokens.
expression = " OR ".join(f'"{term}"' for term in unique_terms)

SELECT parent_asin FROM products
WHERE products MATCH ?
ORDER BY bm25(products, 0.0, 6.0, 4.0, 2.5, 2.5, 1.5, 1.0)
LIMIT ?

The BM25 weights prioritize title (6.0), categories (4.0), features/details (2.5), store (1.5), and description (1.0).

How the evaluator uses the agent

evaluate() calls reset(), creates an initial simulated customer message, then calls respond() for up to 10 turns. The evaluator checks the first 10 valid, unique catalogue IDs using exact parent_asin equality.

If the agent asks about an attribute, customer_reply() reveals a matching simulated constraint. If it does not ask, the customer returns a generic “ask me about one specific attribute” message. Intent Override scenarios send a replacement request on turn 3 or 4.

Metrics are calculated by metric_summary(): Hit Rate@10, MRR, and MTTC. A miss counts as turn 11 for MTTC.

Current limitations

  • No multi-turn memory: previous requirements disappear.
  • No hard filtering: “under $120” is treated as text, not a numeric price condition.
  • No semantic understanding: related phrases such as “something warm for skiing” may not match “insulated winter jacket.”
  • No clarification strategy: ask_attribute is always null.
  • No intent override logic: “Actually, I want hiking boots” is not treated specially.
  • No use of the anonymized user profile.

Useful baseline experiment

The smallest focused improvement is session memory: store prior messages per session_id, combine them with the current message, and search the cumulative query. Measure the change with the existing evaluator before adding embeddings or an LLM.
